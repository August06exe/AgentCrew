# DEV-GUARD — 施工守门协议（二次开发会话开工必读）

> 适用：任何对本仓库进行开发/改动 的 AI 会话或人类。
> 背景：存档架构（见 SAVE-DESIGN.md）——部署后的一切增量信息只进 `_save\`，程序区只读。
> 违反后果：用户数据混入程序区 → 更新丢数据、发布泄隐私。

## 三步守门（每项施工都要走）

### ① 动工前：向主人声明改动清单
开工前用一段话向主人说明：
- 这次要新增/修改哪些**功能**（代码/模板/皮肤 → 程序区）；
- 会不会产生/涉及**增量个人信息**（用户数据、档案、信箱、看板生成物 → 存档区 `_save\`）；
- **判定标准（唯一核心依据）**：程序区的新增信息**包不包含增量的个人信息**——包含，就必须设计进 `_save\`；纯功能实现（不含个人信息），进程序区。
- 拿不准的灰色地带（如"示例数据""演示数据"）：默认按个人信息处理（进 `_save\`），并向主人说明理由。

### ② 施工中：铁律随行
- 一切数据写入走既有工具（`tools\data.py` / `agentcrew_lib` 的存档解析器）——**不新增任何直接写程序区数据文件的代码路径**。
- 新工具/新脚本落盘前自问：这个文件删了存档后该不该自动回来？该回来的=程序区；不该回来的=`_save\`。
- 测试一律用沙箱（`ASSISTANT_DATA_DIR` / `AGENTCREW_SAVE` 指向临时目录），不留测试产物进真实存档。

### ③ 提交前：确定性验收（不靠自觉）
```
python 05-scripts/save.py watch    # 必须 clean
python 05-scripts/doctor.py        # 必须 0 错误
python 06-tests/run_all.py        # 必须 5/5 绿
```
三项任一不过 → 先修再提交。**watch 由脚本判定，不接受"我以为没问题"。**

## 程序区 vs 存档区 速查

| 内容 | 位置 |
|---|---|
| 代码/章程/人设/manifest/模板/皮肤/种子库 | 程序区（git 管理） |
| 数据表 jsonl / config.json / trash / reports | `_save\agents\<id>\data\` |
| 信箱 inbox/outbox（物理） | `_save\agents\<id>\` |
| 主人档案/名册/授权审计/总管信箱 | `_save\master\` |
| 看板生成物 data.js | `_save\agents\<id>\dashboard\` |
| 新装顾问的**程序** | `02-agents\<id>\`（但其数据/信箱立即归档区） |
| 宿主层 cron 注册 | 仓库外（派生态，可重建，不入档） |

## 新增数据表/新功能的标准姿势（二次开发示例）
1. manifest.tables 加表声明（程序区）；
2. 工具改动继续经存档解析器读写（无需关心物理路径）；
3. 若改了表结构 → manifest `save_schema` 升版 + `migrate_save.py` 加阶梯迁移函数；
4. 跑③的三件套验收。
